# Yihop｜讓門市叫貨不再全靠經驗

門市要準備多少食材，不能只看今天還剩多少。遇到下雨、天氣轉冷、農曆初一或十五，需求可能完全不同；廠商哪天休息，也會影響今天該叫多少。

我把這些原本散在紙本、表格和員工經驗裡的資訊，整理進同一個工作畫面，讓門市更容易核對庫存、看到備貨提醒，再產出可以複製到 LINE 的叫貨內容。

**[看看其他作品](https://github.com/garyai8146-jpg/Yihop_LineBOT/blob/main/PORTFOLIO.md)**

## 目前做了什麼

- 把庫存、廠商供貨日與叫貨流程放在 Streamlit 介面。
- 透過中央氣象署 API 取得天氣資料，加入低溫／降雨的規則型備料提醒。
- 使用 `lunar_python` 判斷農曆日期，不必每年手動填入初一、十五。
- 使用 Google Sheets 保存叫貨紀錄；部分寫入採追加紀錄，讀取時保留同品項最新一筆。
- 彙整建議叫貨清單，方便門市人員檢查並複製。

這套系統的重點是**幫人做決定，而不是替人保證訂貨正確**。備貨加成屬於可調整的營運規則，尚未以實際銷售資料證實預測準確度。

## 技術與執行方式

Python、Streamlit、pandas、Google Sheets API、gspread、中央氣象署 Open Data、lunar_python。

```powershell
python -m pip install -r requirements.txt
streamlit run Yihop.py
```

實際啟動需要自行設定私密的 `.streamlit/secrets.toml`（或部署平台 Secrets），包含 CWA `KEY` 和 `[connections.gsheets]`；不要把真實金鑰或表格連結放進 Git。

## 我覺得最值得聊的工程問題

**為什麼先用 Google Sheets？** 因為原本的流程就依賴表格，先接上現場熟悉的工具，導入門檻較低。但 Google Sheets 並不等於完整的交易型資料庫。

**多人一起填單怎麼辦？** 我在部分流程改用追加式寫入，再於讀取時按日期、門市、廠商、品項整理最近的紀錄。這能減少整表覆寫的問題，卻不能保證所有競態、重送或資料一致性問題都被解決。

**外部 API 不穩怎麼辦？** 氣象 API 已恢復標準 HTTPS 憑證驗證；正式導入仍需要處理資料過期、網路中斷與 API 異常。

## 現階段限制

這是可供程式碼檢視的工作流程專案；沒有附上真實門市資料，也尚未完成可公開重現的多店壓力測試。面試時可談實際需求、架構取捨，以及下一步如何加入更完善的權限與資料庫交易保護。
